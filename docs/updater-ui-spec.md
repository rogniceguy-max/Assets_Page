# 沐影盘独立更新器｜原生 WPF 界面结构与验收规范

> **应用范围：** `codex/software-updater` 软件更新专用 UI。本文是更新模块 UI 的**默认设计基线**，与 [软件更新模块设计](software-updater.md) 一起执行。改变窗口层级、交互顺序、控件结构、技术栈或常驻入口前必须取得用户明确同意。
>
> **实现状态：** 该规范由 `desktop/MuYingDrive.Updater/` 的 WPF 窗口和主客户端工作区就绪提示承接；数字签名、实际打包和 Windows 10/11 视觉验收仍未验证。

## 1. 技术与分支边界（强制）

- **唯一客户端技术栈：** .NET 8、C#、**原生 WPF + XAML + MVVM**。主客户端沿用 `desktop/MuYingDrive.NativeWpf/`；独立安装进程的更新 UI 放在 `desktop/MuYingDrive.Updater/` 内，以原生 WPF 窗口显示。
- **禁止** WebView2、React、HTML/CSS、JavaScript Web UI、Electron、Tauri、Chromium/内嵌浏览器。不得以 UI 较复杂、跨平台或易于开发为借口更换。旧 `desktop/MuYingDrive.Wpf/` 和 `frontend/` 仅作历史参考。
- 此分支负责更新提醒、下载/校验状态、进程外安装窗口、失败/恢复界面及底层更新流程。普通文件/登录/传输页面的全局视觉迭代归 `codex/ui-refinement`；只允许为更新功能增加最小必要展示接口，不能顺手重做主界面。
- 更新 UI 遵循同一套已约定的 Radix Slate/Iris 视觉令牌、Lucide 图标和 Light/Dark/跟随 Windows 主题；不得自造第二套色板、随机图标或大幅动画。更新器可通过共享资源或构建期确定的资源副本复用令牌，但不得要求原主客户端进程继续运行。

## 2. 必须采用的总体交互结构

1. **后台阶段：** 主客户端正常运行期间检查更新、后台预下载和验证；除真实错误外不弹出进度窗口、不增加导航页、登录页版本信息、主窗口底部常驻状态栏。
2. **就绪提醒：** 只有包来源、清单签名、版本规则及哈希校验通过后，才呈现简洁的「新版本已准备就绪」提示，操作限定为「立即更新」「退出后更新」；提示应低干扰。用户已确认将其作为文件工作区内的短暂轻提示，不增加常驻入口。
3. **安全退出：** 点击「立即更新」必须先检查文件传输能否安全暂停/保存检查点，并提醒外部程序未保存的文件不能由沐影盘自动保证保存。无法安全暂停时拒绝强制安装；仍允许下次退出后再更新。
4. **独立更新窗口：** 主客户端彻底退出且更新器确认进程句柄已释放后，启动**独立 WPF 窗口**展示安装状态。该窗口不能依赖主应用 UI 进程，不复用尚存活的主进程 WebView。
5. **安装完成或失败：** 成功可提示「更新完成」并提供「启动沐影盘」；失败或已回退必须明确说明旧版本是否可用以及必要的恢复/重试入口，不能无依据显示成功。

## 3. 进程外更新窗口：固定布局基线

设计目标：**类似一个紧凑的 Windows 原生更新窗口，而不是一个独立的管理后台或多页面安装向导。**

- 默认宽度 **460 DIP**（允许布局因系统字体/缩放调整，建议可用范围 400–520 DIP）；内容建议高度 **约 280–320 DIP**，失败详情可增加高度或滚动；居中显示在可用工作区，尊重 Windows DPI 和安全边界。
- 顶层顺序冻结为：**窗口标题栏 → 分割线 → 当前阶段主标题 → 一行解释文字 → 进度条或阶段活动标记 → 底部阶段文本和可核实的进度值 → 按状态显示的操作区**。
- 主内容内边距 **24 DIP**；元素垂直间距使用 **8 / 12 / 16 / 24 DIP**；不要新建侧栏、底部常驻导航、面板统计卡、营销背景/插画、多步骤向导左侧轨道。
- 独立更新窗口允许显示「沐影盘更新程序」作为窗口名称；**这不是授权恢复主客户端顶栏 Logo 或品牌名称**。默认标题左侧可使用低调的 Lucide 更新图标，所有状态需同时用文字传达。
- 显示真实进度时用细进度条和右侧百分比；百分比由实际可测量工作量计算。**安装/验证过程没有可靠总量时必须使用不确定进度状态，不显示硬编码百分比、64% 示例值、虚构剩余时间或循环假数字。**
- Light/Dark 使用现有 Slate/Iris/语义色，绿色仅用于确认完成，红色用于真实失败；默认使用平静的中性色界面。满足清晰焦点、屏幕阅读器、无障碍对比和 Windows 减少动画设置。

### 3.1 字符布局草图（结构约束，不是 Web/HTML 实现）

```text
┌────────────────────────────────────────────────┐
│ ↻ 沐影盘更新程序                           —  × │  ← 原生 Windows 标题栏
├────────────────────────────────────────────────┤
│                                                │
│ 正在安装新版本                                 │  ← 当前阶段，主标题
│ 正在验证和应用更新，请勿关闭更新程序。          │  ← 一句说明
│                                                │
│ ━━━━━━━━━━━━━━━━━━━━━━━────────────             │  ← 真实进度；否则不确定态
│ 正在安装文件                      进度 64%      │  ← 仅布局占位，禁止写死 64%
│                                                │
│                                                │
└────────────────────────────────────────────────┘
```

**警告：草图中的 64% 仅用于说明数字的位置；任何生产界面不得写死该数值。** 没有可信进度时右侧应为空，并由文字说明当前阶段。

### 3.2 实际元素与绑定要求

| 顺序 | 元素 | 文案 / 数据来源 | 约束 |
| --- | --- | --- | --- |
| 1 | 标题栏 | 「沐影盘更新程序」 | 原生窗口标题栏，支持系统窗口管理与键盘操作 |
| 2 | 分割线 | 视觉分隔 | 使用统一 Slate 边线 |
| 3 | 阶段标题 | 例如「正在安装新版本」 | 必须映射真实更新状态，不得无故跳阶段 |
| 4 | 简短解释 | 例如「正在验证和应用更新，请勿关闭更新程序。」 | 每个状态一到两行；不展示密码、令牌和敏感路径 |
| 5 | 进度控件 | 安装/校验提供的真实进度，或不确定态 | 避免模拟百分比与假倒计时 |
| 6 | 底部状态 | 例如「正在安装文件」及可核实的百分比 | 切换状态时同步更新，出错给出明确原因 |
| 7 | 操作区域 | 等待退出、验包和解压阶段提供「取消更新」；成功或已回退后提供启动入口；恢复状态不明时只提示联系管理员 | 开始切换安装目录后取消按钮收起且窗口不可关闭 |

## 4. 窗口状态与文案

| 底层阶段 | 标题 | 辅助说明 | 进度 / 操作 |
| --- | --- | --- | --- |
| `WaitingForExit` | 正在准备更新 | 正在等待沐影盘安全退出。 | 不确定态；不得强杀客户端或中断传输 |
| `Verifying` | 正在验证更新文件 | 正在检查安装包的完整性和可信发布信息。 | 可度量才显示确定进度 |
| `Installing` | 正在安装新版本 | 正在应用已经验证的更新文件。 | 真实进度或不确定态，禁止虚构 ETA |
| `Validating` | 正在完成更新 | 正在检查新版本是否可以正常启动。 | 启动健康检查的可信结果 |
| `Succeeded` | 更新完成 | 已成功安装新版本。 | 完成标记；「启动沐影盘」 |
| `FailedRolledBack` | 更新未完成 | 安装遇到问题，旧版本已恢复，可继续使用。 | 明确失败、可安全重试才展示「重试」 |
| `FailedRecoveryNeeded` | 更新需要处理 | 更新未成功，无法确认旧版本可用，请联系管理员。 | 明确可操作的错误详情与日志位置（不暴露秘密） |

**状态名是 UI/更新器契约建议，具体代码字段由更新分支统一定义。** 不能仅通过界面状态判断安装成功；`Succeeded` 必须来自版本切换、必要校验/健康检查的真实成功信号。

## 5. 交互与错误处理

- 「立即更新」与「退出后更新」只出现在主客户端的**就绪提醒**；独立安装进程中不要再要求用户重新确认一次安装。
- 若传输不能暂停或检查点未落盘，提示原因并保留原客户端运行；不能以更新优先为由取消文件任务。
- 更新器关闭按钮：等待客户端退出、清单/安装包验证和暂存解压阶段可请求安全取消；取消后保留并提供启动当前版本的入口。开始原子目录切换后不提供取消，窗口关闭被阻止，直到健康确认或安全回滚。
- 安装失败显示人类可读的简短说明；每次事务在本地保留状态 JSON 和追加式 JSONL 事件日志，不直接暴露账户凭据、Token、内部服务密钥或用户文件路径。
- 明确处理高 DPI、125%/150%/200% 缩放、屏幕阅读器、键盘 Tab、Enter、Esc、深浅主题、离线、更新包错误、回滚，以及小屏工作区。
- 不引入营销图、彩色大卡片、版本更新日志大页面、文件浏览/传输导航、计时器、统计数据、第三方 UI Kit、二级向导流程或更新强制弹屏。

## 6. UI 评审与验收清单

- [ ] 独立更新窗口由 WPF/XAML/C# 实现；依赖树和项目文件中未引入 WebView2/React/HTML UI 运行时。
- [ ] 窗口主要区块顺序与第 3 节相符；无新增导航、额外欢迎页、品牌顶栏；数字没有模拟数据。
- [ ] 没有更新时不干扰用户；包安全校验完成前不显示「已准备就绪」。
- [ ] 手动更新、退出后更新、不可安全暂停任务、更新包损坏、安装失败、回退成功/失败均显示对应真实状态。
- [ ] 关闭主客户端后独立更新窗口仍可运行，等待主进程退出且句柄释放。
- [ ] Windows 10/11 原生界面、键盘操作、系统缩放、浅/深主题、屏幕阅读器焦点实测；未测试的项明确标注「未验证」。
- [ ] UI 改动没有修改 NAS ACL、Samba 认证、文件传输业务或 `codex/ui-refinement` 分支内容。

**与产品决策的关系：** 已确认 NAS 托管、后台预下载、手动/完全退出后更新及不打断使用。用户已选择在文件工作区内显示短暂轻提示；当前实现 30 秒后自动收起。更新器的专用窗口结构是本次明确采纳的设计基线；变更必须由用户批准。
