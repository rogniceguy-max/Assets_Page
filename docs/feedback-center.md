# 沐影盘｜匿名反馈中心：产品、UI 与实现约束

> **状态：设计基线已获确认；反馈功能已在本分支实现，未部署生产 NAS。实现与验收记录见 [feedback-implementation.md](feedback-implementation.md)。**
>
> 分支：`codex/feedback-center`，来源：`codex/nas-smb-v2`。
> 技术栈：**.NET 8（net8.0-windows）+ C# + 原生 WPF + XAML + MVVM**，禁止 WebView2 / React / Electron / Tauri 代替现有客户端。
>
> 本文是新增反馈中心的专项规范：新增一级「反馈」入口是用户对既有 Notion「文件/传输」导航的**明确新增功能批准**，不授权修改其余已确认的导航、登录、文件权限和传输规则。与原 UI 规范冲突的只有这项被批准的新增入口，其余继续遵守。

## 1. 目标与角色

所有**已登录员工**可进入反馈中心，阅读已公开的问题反馈和功能建议，匿名提交文字及可选截图；负责维护的人员可以评估并更新状态。反馈记录及 UI 必须完全不展示提交人的姓名、账号、所属部门、个人头像、稳定匿名代号或可据此追溯的标识。

**两类反馈必须并列支持：**
- **问题反馈**：例如上传/下载失败、NAS 权限错误、文件显示异常等；可选择问题类型、标题、经过、复现步骤、图片。
- **功能建议**：例如希望新增文件操作、交互优化；填写建议标题、使用场景、预期收益，可上传草图/截图。

员工可以阅读全部公开反馈，但不自动有权修改、删除、关闭其他人的记录；状态由明确授权的维护角色管理。**首版不提供「我的反馈」**，因为无身份关联时无法安全识别谁提交了哪条记录；也不显示提交者、评论用户或排行榜。无需实现投票、私聊、讨论区、通知系统或复杂工单功能。

## 2. 导航入口和页面层级（本次批准）

当前侧栏上方主导航 `文件`、`传输`，允许新增**第三项 `反馈`**（Lucide MessageSquareText 或现有控件支持的语义等效图标）。下方分隔的 `空间` 中依旧是 `本部门`、`公共素材`、`个人空间`、`其他部门`，不要将反馈放在部门空间下面或混入文件右键菜单。折叠侧栏时保持图标可点击、可键盘聚焦、带 Tooltip 和可访问名称。

**「文件」是文件管理工作区入口，不代表「所有文件」聚合：** 点击它保留上次选中的空间；点击具体空间会打开文件页并切到相应 NAS 目录。反馈页面是独立于 SMB 文件树的第三个工作区，切换时不得销毁 `FilesViewModel` 浏览上下文或 `TransferViewModel` 后台传输任务。

建议主页面版式：标题「反馈」；右侧一个主要按钮「新建反馈」；搜索；分段筛选「全部 / 问题反馈 / 功能建议」；按最近更新时间或提交时间排序的公共列表；详情可在中央工作区独立呈现，返回保留列表位置与筛选。禁止常驻大统计卡片、社交信息流、公告栏、底部状态栏或首页式 Dashboard。

「新建反馈」建议采用居中 WPF 对话框、紧凑布局：类型选择 → 标题 → 描述（可选复现步骤/场景）→ 截图（可选）→ 发布前预览/隐私提示 →「提交反馈」。**绝不显示或默默绑定作者姓名、部门或账号头像。** 上传图片优先支持 Windows 文件选择、原生拖入和粘贴截图；禁用 WebView 上传控件。

## 3. 匿名性与隐私：实现的硬性要求

**匿名不只是隐藏姓名。** 反馈记录、对外 API、附件、检索索引、可导出的诊断数据及 UI 不得存储或回传提交人标识。具体要求：

1. 仅利用现有登录会话在**提交请求时**检查是否有权使用反馈中心；业务反馈表**不得写入**用户 ID、用户名、部门、邮箱、头像、稳定化名、会话 ID、设备 ID、客户端持久安装 ID、原始 IP、User-Agent 指纹或与其可关联的外键。
2. 反馈实体可以有**随机反馈编号**、内容、类别、状态、公开附件引用和创建/更新日期；随机编号不能编码用户/部门信息。不得以「我的反馈」功能为名保存秘密的作者映射表或长期可链接 token。
3. **必须排查并最小化服务端访问日志、反向代理、应用监控、异常追踪和备份**可能留下的 IP、认证信息、请求内容、附件原文件名、User-Agent、请求关联键。禁止日志写入 Session Token 或上传文件内容。部署前专门验收日志/监控的可识别性，并如实披露无法消除的基础设施关联风险。
4. 用户上传的图片应服务端重新解码/编码（去 EXIF 和其他元数据），不保留原始文件名；限制实际格式（例如 PNG/JPEG/WebP）、魔数与像素/尺寸/数量/总大小，阻断恶意文件和路径穿越。图片**像素本身可能显示姓名、聊天或客户数据**；在提交前强制提供预览和明显的“请遮盖敏感内容”提示。自动填充的错误摘要需脱敏。
5. 公共反馈内容默认公司所有已登录员工可读，不对外开放；敏感/可疑内容在公开前进行合适的安全检查与隔离处理，可由明确授权的维护人员隐藏，不能把原始诊断日志直接公开。
6. 防滥用采用**不长期保留身份标识**的短窗口限流、文件大小配额和内容检查；不要为实现限流在业务数据库建立身份画像。若业务确实需要跨请求身份追踪，**先请求用户批准新的隐私权衡**，不能破坏“完全匿名”要求。
7. 对管理员的状态变更可在**与提交者匿名机制隔离**的运维审计记录中记录授权操作和处理结果，但不能反查原作者；普通员工查看反馈时只显示状态，不显示维护人员身份。

**真实性边界：** 在现有认证及 NAS/网络基础设施未完成日志审计前，不可以对外声称「任何管理员或服务商都绝对无法追溯」。首版目标是**应用层不可关联提交者**，并进一步对基础设施数据最小化。既有账户系统仍用于访问控制，但不能把登录用户作为反馈作者写库。

## 4. 数据、API 与安全边界（设计契约；实现细节见专项验收记录）

- NAS V2 HTTPS 服务独立新增反馈模块，不复用 SMB「公共素材」/部门/个人空间，也不修改 Samba ACL 或既有业务文件树。反馈记录数据库/索引与附件存储逻辑隔离；使用独立受控路径，附件通过认证后的不透明 ID 路由访问。
- 建议接口：`GET /api/v2/feedback`（公开列表/过滤/分页）；`POST /api/v2/feedback`（匿名提交）；`GET /api/v2/feedback/{id}`（详情）；经认证的附件上传/下载接口；受维护角色保护的状态/隐藏接口。具体 URL 和数据模式实施前应核对现有 V2 HTTP 服务。
- 公共查询响应只包含：`feedback_id`、`kind`、`category`、`title`、`description`、`status`、`created_at`、`updated_at`、`attachments`；**绝不包含 author / reporter / user_id / department 等字段**。附件无需公开原始敏感路径。
- **角色权限必须真实存在才能开放管理操作**；当前 V2 若无维护人员身份/角色模型，先完成最小隔离设计与测试，不能让任何登录员工更改全体状态，也不能借反馈项目直接修改现有 NAS/Samba 用户与权限体系。
- 提交成功必须以服务端确认数据库/附件持久化结果为准；失败明确说明、保留尚未提交的表单文字，不展示虚假成功。反馈存储故障不能阻塞登录、文件访问、真实文件传输或客户端软件更新。
- 文件传输、软件更新和反馈附件采用各自独立的任务/缓存目录，不交叉污染。版本迁移/删除附件应有审计及恢复边界；不对生产 NAS 擅自部署、重置数据库或调整共享权限。

## 5. 反馈状态与内容

| 类型 | 首版状态示意 | 用户可见动作 |
| --- | --- | --- |
| 问题反馈 | 待处理、处理中、已解决 | 查看、搜索、提交新问题 |
| 功能建议 | 待评估、计划中、已采纳、暂不考虑 | 查看、搜索、提交建议 |

状态代表维护团队真实决定，禁止自动将建议标记「已采纳」或把仅创建成功的问题标记「已解决」。不在列表展示作者、部门、稳定匿名昵称；可显示普通反馈编号、时间、类型、是否带图片。

## 6. 分支职责、避免跑偏

- 当前仅在 `codex/feedback-center` 实现反馈专属原生 WPF 视图/控件/ViewModel，以及 NAS V2 反馈业务接口与存储；引入菜单入口应只做最小必要 `WorkspaceView.xaml` / `WorkspaceViewModel` 变更。
- `codex/ui-refinement` 继续负责通用原生 WPF 视觉、主题和其它文件/传输页面改进；本分支复用 Slate/Iris + Lucide 资源，不自造技术栈和视觉体系。
- `codex/software-updater` 继续负责版本更新；本分支不得修改其流程和窗口。
- **禁止**更改 `frontend/` 或 `desktop/MuYingDrive.Wpf/` 的 WebView2/React 旧原型，也禁止改 `main`、SMB ACL、NAS 账号/会话模型、原有登录和文件传输底层或生产运维配置。
- 原有 Notion UI 文档将一级导航标记为「文件」「传输」，本次用户**明确批准增加「反馈」**，仅是此一项例外；后续应将新增确认事项同步回 Notion 专项规范，并在合并时处理各分支对 `WorkspaceView` 的冲突，不能拿旧文档中“禁止新增导航”一条来删除反馈入口。

## 7. 开发与验收

- [ ] 可验证分支来源 `codex/nas-smb-v2`，只提交反馈相关文件；不修改 `net8.0-windows`、不引入 WebView2/React。
- [ ] 登录员工均可看公开列表，匿名提交**问题反馈和功能建议**；未登录访问拒绝；权限边界由后端强制执行。
- [ ] 公共页面、数据库、API、附件元数据不包含作者相关字段；没有「我的反馈」、作者头像或稳定匿名化名。
- [ ] 上传正常截图，限制不合规附件、超大文件、伪造 MIME、畸形图和路径穿越；服务端去除图片元数据；上传前提示图片像素可能泄露身份。
- [ ] 检查 NAS/API/反向代理/监控/日志是否意外保存身份信息；任何未核实项标为**未验证**，不承诺绝对匿名。
- [ ] 传输页没有反馈快捷入口、关联点击处理或诊断预填；仅通过侧栏「反馈」工作区提交。
- [ ] 文件工作区位置保留、上传/下载任务继续；切换反馈页没有破坏传输检查点和原有导航。
- [ ] 普通员工无法篡改状态；管理角色变更有授权校验；公开内容可以被适当审核/隐藏。
- [ ] Windows 10/11 下验证 WPF 编译、Light/Dark、键盘、可访问性、高 DPI、空/加载/错误页和多图展示。
- [ ] 分支未合并，未对生产 NAS 服务、数据库或 Samba 配置产生任何变更；上线需用户另行批准。
