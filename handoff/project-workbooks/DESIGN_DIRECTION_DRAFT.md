# 文件管理与项目空间方向

状态：当前设计方向，依据对话中已确认的导航、权限和资产关系整理。`11 · 节拍工作表`的内部结构仍未定，不在本次改造范围内。

## 导航

- 全局主导航：`图片`、`视频`、`个人空间`、`传输`、`反馈`。
- `项目 +`是独立的导航分组。用户点击“+”后创建并命名一个空间；空间名称可改，创建后出现在该分组下。
- 每个项目导航树包含默认工作簿`节拍表`、`资产表`，以及项目的图片文件夹和视频入口。
- 全局`图片`、`视频`页按项目分组展示所有项目的媒体；进入项目树里的媒体节点后，只显示该项目或具体文件夹的内容。
- `个人空间`独立于项目，只允许所属用户查看和读写。项目不按部门划分；所有用户都能读写项目及其中的媒体。

## 项目与工作簿

创建项目时，后端一次性创建空间以及两份默认工作簿：`节拍表`和`资产表`。界面收到服务端确认后的项目、工作簿快照后，才把它们显示在导航树中。项目名称可重命名，稳定 ID 不随名称变化。

用户打开工作簿后，仍像打开表格文件一样直接看到完整表格内容；转换过程不作为用户步骤，也不在用户界面展示。现有工作簿查看控件作为项目壳层内容复用。项目首页不再放项目切换下拉框或重复的新建模板按钮。

## 资产行与图片文件夹

在`资产表`创建资产行时，后端同时创建或绑定项目内的图片文件夹，并返回稳定的行 ID、文件夹 ID 和路径。例：项目“孟婆”里的`角色 / 孟婆`对应`图片/角色/孟婆/`；该文件夹随后出现在左侧“孟婆”项目导航树中。

把图片拖到资产行的`备选`列，就是把图片放入该资产文件夹并关联到同一行；一张图片在图片库和工作表中是同一个文件对象，不复制出另一份。`选定`仍是一张图片，可从素材库选择或拖入。现有的评论和“好 / 不好”评价继续关联原图片及作者。

从资产行移除图片只将其移入项目回收站并隐藏，不物理删除原文件，也不丢失评论和评价；恢复时回到原文件夹。工作表关联、文件夹归属、评论和评价通过稳定 ID 关联。名称修改不应使这些关系失联。

## WPF 与后端接入边界

WPF 壳层负责导航、项目/文件夹视图、拖放交互、媒体展示和回收站入口；项目创建、模板初始化、资产行与文件夹的原子创建、媒体查询/上传/软删除/恢复及个人空间权限都需要宿主 API 支持。未接通 API 前，界面不能本地伪造成功状态或编造文件夹节点。

后端接口至少应支持：

- 创建/重命名项目，并在创建时原子初始化`节拍表`和`资产表`。
- 列出项目与工作簿、项目树中的资产文件夹，以及跨项目按项目归组的图片/视频。
- 创建资产行并原子返回该行对应的图片文件夹；向文件夹上传/归属图片并关联到资产行。
- 将图片从当前资产视图移入项目回收站，保留评论、评价和原文件；列出回收站并恢复至原文件夹。
- 以登录用户为边界访问个人空间；项目对所有已登录用户开放读写。

## 暂不决定

- `11 · 节拍工作表`的文件夹关系、行模型及导航方式。
- 多行引用同一图片时，移入回收站对其他引用的影响。
- 视频与资产行之间是否建立类似图片的关系；当前只确认视频按项目组织和浏览。
