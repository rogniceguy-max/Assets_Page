# 给接手 AI 的合并任务

按用户已确认的文件管理方向接入本包。先读本文件、[DESIGN_DIRECTION_DRAFT.md](DESIGN_DIRECTION_DRAFT.md)、[wpf/INTEGRATION.md](wpf/INTEGRATION.md) 与 `contracts/WORKFLOW_V3.md`。本包是隔离的 WPF/API 交接源码，不代表已接通主程序。

## 用户已确定

- 左侧全局主导航为`图片、视频、个人空间、传输、反馈`；另有`项目 +`分组，用户创建、命名并可重命名共享项目。
- 所有用户都能读写项目。个人空间只允许本人查看和读写，不按部门拆分项目权限。
- 新项目原子创建两份默认表：`节拍表`与`资产表`。用户打开时像表格文件一样查看完整表格，不展示转换过程。
- 全局图片/视频页浏览全部项目的媒体并按项目分组；项目导航树可进入本项目媒体和资产图片文件夹。
- 资产表创建资产行时同时创建或绑定图片文件夹，如`角色 / 孟婆`→`图片/角色/孟婆`。拖放到备选列即进入该文件夹并显示为同一个媒体对象。
- 移除备选是可恢复的软删除，进入回收站后可恢复到原文件夹。图片评论和“好 / 不好”评价不丢失。选定原因与历史不需要。
- 节拍表内部模型仍未定；本次不预设节拍行到文件夹的关系。

## 接入顺序

1. 检查当前重构中的文件和未提交改动，不覆盖其他 AI 的工作。
2. 实现/调整后端契约：项目创建和默认表初始化、项目树快照、资产行与图片文件夹原子创建、跨项目媒体查询、向资产文件夹归属图片、回收站软删除/恢复、私有个人空间 ACL。项目端点需使用现有登录身份和服务端授权。
3. 将`ProjectSpaceShell`挂入现有主窗口左栏；在主程序中接事件并调用 WPF `Apply...` / `Replace...`，只在后端确认后更新界面。工作簿页使用现有控件，资产行创建成功后刷新项目树。
4. 复用宿主认证 HttpClient 和主题资源。账号或服务器切换时销毁旧页面/VM，避免旧空间状态和缓存泄露到新会话。
5. 后续获得用户解除“不要运行程序”的限制后再构建、运行及验收；否则只做源码静态核对并如实记录未编译。

## 不能假定

- WPF 控件的事件不等于 API 已实现；服务缺失时不得返回假成功或在本地伪造项目、工作簿、资产文件夹和回收站状态。
- 资产文件夹、工作簿图片引用、评论和评价应以稳定 ID 关联，文件夹重命名不能使工作表或讨论失联。
- 同一媒体被多个工作表引用时软删除的范围还需要后端定义；在该语义明确前，API 必须拒绝有歧义的破坏性状态变更，而不能物理删除原文件。
- 当前包不是完整 Excel 排版/公式引擎；不得丢弃未知工作表、列或原始批注，也不得把静态检查称为运行验收。
