## 用户已确认的行为

1. 全局主导航为“图片、视频、个人空间、传输、反馈”；另有“项目 +”分组。点击“+”创建、命名项目，项目可重命名。
2. 所有项目成员可读写；个人空间只对本人可见可读写，不再按部门拆分共享空间。
3. 新项目默认生成“节拍表”和“资产表”。界面像表格文件一样直接显示完整表格，不向用户展示转换过程；只接受 `.xlsx` 导入或模板创建。
4. 全局图片/视频页展示全部项目的媒体并按项目分组；项目树下的媒体节点显示该项目及具体图片文件夹内容。
5. 资产表创建资产行时，同时创建/绑定图片文件夹，例如`角色 / 孟婆`对应`图片/角色/孟婆`。拖入备选即把图片放入该文件夹并关联同一个文件对象。
6. 移除备选是软删除/隐藏并进入回收站，可恢复到原文件夹；评论和“好／不好”评价留在原图片对象上。选定仍是一张图片，不要求填写原因，也不记录选定历史。
7. 节拍原文只读，制作规划和红黄绿可编辑；节拍本身可讨论。原六列成员批注保留来源，不能把未知作者改成当前登录人。`11 · 节拍工作表`的导航及文件夹模型仍未确定。

## 合并方法

优先以 `ProjectReference` 引入 WPF 类库，隔离命名空间 `MuYingDrive.ProjectWorkbooks`，不要把整份宿主 `App.xaml` 或 `WorkspaceView.xaml` 覆盖掉。后端也以独立模块接入，在现有 stdlib handler 的 GET/POST/PUT/DELETE 路由前增加本模块分流；不另引入 FastAPI 或第二套登录。

已知宿主位置：`work/Assets_Page/desktop/MuYingDrive.NativeWpf` 和 `work/Assets_Page/backend/v2`。这些路径是参考，不要假定重构后的文件结构完全没变。合并前重新读取现有变更。

推荐顺序：

1. 阅读现有重构与用户要求，确认工作簿身份/素材接口和权限模型；不覆盖别人尚未完成的编辑。
2. 先实现后端适配器：现有 session 验证、项目空间与个人空间权限、项目目录、原 xlsx 存储、两模板原子创建、资产行/图片文件夹关系、媒体查询与回收站、完整读取、修订及幂等、当前快照导出；再接入独立事务存储。
3. 接入新路由，并按WORKFLOW_V3.md优先、API.md及REVIEWS.md补充对齐响应。DTO使用snake_case；分页返回明确游标，不能静默截断。导出受影响的修改必须使快照版本增长/失效。
4. 引入 WPF 类库。用宿主 HTTPS client/handler 和逐请求 token 提供器创建 HTTP service，再创建 ViewModel。
5. 在主窗口左侧导航区域接入`ProjectSpaceShell`，并将现有`ProjectWorkbooksView`作为壳层工作簿内容。按 [WPF 接入说明](wpf/INTEGRATION.md)转发项目、媒体、文件夹和工作簿事件。
6. 复用宿主主题键。独立回退资源只用于缺少宿主资源的情况，不覆盖宿主动态主题。图片弹窗也要获得相同资源。
7. 在用户允许运行后再构建、测试、检查真实截图，并完成 `ACCEPTANCE.md`。禁止把本次静态审阅描述为编译通过。

## 必须知道的实现边界

- **后端路由与图片关系存储是参考实现；NAS、现有素材库、工作簿解析及真实模板创建通过明确适配器接入。** 不包含一个虚构的 allow-all 存储服务。缺少适配器时不要返回假成功。
- **WPF 类库没有 App/入口，不是双击即开的独立应用。** 由现有 Workspace 注入服务后显示。认证 HttpClient 的所有权和生命周期由宿主管理；不能为图像另建绕过证书固定或授权的网络通道。
- 两个模板的 UI 是业务表格阅读布局，不是完整 Excel 排版/公式引擎。通用工作表提供全部单元格值的纵向兜底并明确 `values_only`；复杂原格式通过保留的原文件访问。若后续要求合并单元格/图表/公式重算逐项保真，必须补充真正的工作簿渲染层，不能称此包已实现。
- 业务字段抽取不得丢失未知列/工作表：适配器需要保留额外通用工作表或拒绝不支持的表示。旧 import parser 的 ignored 列/图片不能直接当作完整读取结果。
- 此包增加节拍规划/等级编辑及当前版本导出调用，但**真实xlsx导出引擎仍需宿主适配器**，必须把当前文字、图片和讨论写入真实工作簿；缺失时503，不得下载原件冒充导出。通用Excel单元格编辑、公式重算、图片图层编辑仍非本包提供。
- WPF 原生图片解码优先 PNG/JPEG。后端存储 WebP 时为查看接口提供 PNG/JPEG 转码，或接手 AI 明确加入解码器；不要默默把 WebP 显示为空。
- v3素材目录使用分页；工作簿及讨论仍完整读取。缩略图按需加载不代表无限规模性能已验证，仍须用真实工作簿和107张素材在宿主中验收。

## v2 评价的使用方式

图片旁显示“好 N／不好 N／评论 N”；点图进入大图和评审区，不跳进另一层管理页。登录成员点“好”或“不好”提交自己的票，也可撤回；可以直接写评论而不投票。自己发表的评论可修改或删除，其他成员的评论只读。评论使用独立记录，不再用一条随投票覆盖的批注代替讨论。

通过选定图片选择器将现有备选选为选定时，备选关系及评价保留；更换成另一图片不继承旧票数。对角色/场景本身的整体要求写在“资产讨论”中，独立于图片。统计请求失败显示不可用而非误报零票；v3.1打开时读取、失败可重新加载，没有常驻刷新、后台轮询或实时推送。
